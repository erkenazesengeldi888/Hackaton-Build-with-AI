# Гид по Астане — ИИ-помощник по прогулкам (RAG)

Задача НИЦ Smart City: показать рабочую RAG-систему, которая в реальном времени подсказывает, **куда сходить и что сделать**, исходя из локации, предпочтений и контекста.

## 1. Концепция продукта

**Идея.** Человек пишет, чего хочет («тихое место с кофе», «адреналин», «с собакой»), и выбирает, где находится (Mega Silk Way, Байтерек, Хан Шатыр, EXPO, Набережная; для заведений в том же здании расстояние считается 0). Система находит реальные места рядом, объясняет «почему» именно они, сколько времени на них уйдёт, что там делать, и прокладывает путь пешком или на авто.

**Целевая аудитория:** жители Астаны («куда пойти сейчас»), туристы с ограниченным временем, семьи с детьми, компании до 20 человек, владельцы собак, люди с ограниченной подвижностью.

**Сценарии использования:** быстрый выбор на ближайший час; планирование вечера для компании; мини-маршрут из 3 мест с таймингом; поиск по особым условиям (вид, терраса, адреналин, питомцы).

## 2. Как работает RAG (высокий уровень)

1. **Данные (POI).** Реальные заведения Астаны: OpenStreetMap (название, координаты, категория, теги, часы) + оценки и часы 2GIS, внесённые командой вручную с датой проверки. Только места с адресом. Сбор автоматизирован скриптами `scripts/` (выгрузка OSM → сопоставление с оценками 2GIS по адресу → сборка `data/pois.json`).
2. **Retrieval.** (a) гео-фильтр по радиусу от точки пользователя; (b) текстовый поиск TF-IDF по тегам, категории и описанию с словарём синонимов («с видом» → вид/панорама, «адреналин» → картинг/дрифт); (c) разбор критериев запроса: для каждого места проверяется, **подтверждён ли** критерий данными (✓), нет данных (?) или не выполняется (✗); (d) ранжирование: релевантность + оценка и число оценок + расстояние + подтверждённые критерии; закрытые места понижаются; для групп до 20 чел. поощряются места с залами и активностями.
3. **Generation.** Найденные места с критериями, расстояниями и часами работы передаются в LLM (Gemini) с жёстким системным промптом: только места из контекста, формат «почему / время / что делать / данные», честные пометки. Без ключа Gemini работает шаблонный генератор с тем же форматом.
4. **Маршрут.** Реальные дороги (OSRM на данных OSM): пешком, на самокате (велопрофиль), на авто; автобус и ЛРТ — оценка по остановкам и станциям OSM (пешком до остановки + поездка + пешком), без расписания; пошаговые подсказки, время с остановками, кнопка «Собрать мини-маршрут из 3 мест», ссылки в Google Maps и 2GIS.

## 2а. Дополнительные функции

- **«Найти приключения!»:** рулетка с анимацией выбирает место в радиусе (чем выше рейтинг и ближе, тем больше шанс).
- **Погода:** плашка с температурой и ветром (Open-Meteo, обновление раз в 15 минут). В мороз, при сильном ветре или осадках уличные места опускаются в выдаче.
- **«Успеете»:** под лучшим выбором — туда + на месте + обратно против заданного времени.
- **Такси:** ссылка с подставленными координатами (Яндекс Go).

## 3. Формат ответа (по ТЗ)

Для каждого сценария 1–3 пункта, у каждого три короткие строки: **Почему** (данные POI), **Время** (на месте и с дорогой против времени пользователя), **Что делать** (идея). Подробнее: **Почему** (какие критерии запроса подтверждены данными, какие нет), **Что делать**, **Данные** (источник и часы работы). Пример: см. [TEST_SCENARIOS.md](TEST_SCENARIOS.md).

## 4. Честность, неполные и сомнительные данные

| Ситуация | Как система себя ведёт |
|---|---|
| Критерия нет в данных (например, «терраса», «можно с собакой») | Помечается «?» и «в данных об этом нет — уточните на месте»; не утверждается. Если нет ни одного места с подтверждением, в ответе явное предупреждение. |
| Нет часов работы | «Часы не указаны — вероятность, что работает сейчас, неизвестна»; слов «открыто/закрыто» нет. |
| Часы есть | Показываются как есть (из 2GIS или OpenStreetMap), без утверждения «открыто/закрыто»; места, закрытые по этим часам, понижаются в выдаче. |
| Место не работает по известным часам | Понижается в выдаче (на экране статус «открыто/закрыто» не показывается). |
| Оценка относится к другому филиалу сети | В карточке явно: «оценка филиала по адресу …, у этого филиала может отличаться». |
| Координаты получены по адресу | «Положение на карте приблизительное». |
| Идея vs данные | Названия, расстояния, оценки, теги, часы — данные; пункт «Что делать» помечен «(идея, не из базы данных)». |
| Сервис маршрутов недоступен | Показывается прямая линия и грубая оценка с предупреждением. |

Оценка «сервиса» у мест из 2GIS равна общему рейтингу 2GIS (отдельной оценки сервиса в данных нет).

## 5. Этика и приватность

- **Координаты пользователя** используются только для расчёта расстояний в рамках сессии; не сохраняются, не логируются, не передаются третьим лицам. Пользователь сам выбирает точку из списка (геолокация браузера не запрашивается).
- **Своё место:** если пользователь вводит адрес или название, оно сначала ищется среди заведений базы, затем отправляется в OpenStreetMap (Nominatim) для определения координат; результат не сохраняется.
- **В LLM** уходят только текст запроса и данные о местах; координаты пользователя не передаются, только рассчитанные расстояния.
- **Прозрачность:** над результатами всегда видна полоса «Использованные данные» (локация, фильтры, теги, критерии запроса, источники). В каждом ответе и описании места метки «Данные POI» (из базы) и «Идея» (сгенерировано) разведены; под каждым местом показаны теги, «Совпало» (какие фильтры и критерии совпали) и источник.
- **Недостоверная информация:** см. таблицу выше; система не придумывает места, цены, меню, рейтинги.
- **Безопасность:** рекомендации не содержат персональных данных; контакты берутся из открытых источников; для активных форматов (картинг) напоминание про ограничения и бронь.
- **Ограничения:** оценки внесены вручную и устаревают; данные OSM неполны.

## 6. Тестовые сценарии

8 сценариев (3 пользовательских + 5 из ТЗ) с входом, контекстом и фактическим ответом: [TEST_SCENARIOS.md](TEST_SCENARIOS.md). Часть сценариев (розетки, детские площадки, «ночная активность») намеренно показывает слабые места данных: система честно помечает, чего не знает.

## 7. Ограничения и риски

- Нет данных о среднем чеке и парковках: фильтр по бюджету и условие «парковка рядом» не реализованы. Нужны данные 2GIS (средний чек) — можно добавить в `ratings.csv`.
- Ссылка на такси использует публичный формат Яндекс Go и не проверена в приложении.
- База небольшая (≈118 мест с адресом, оценки у 45): охват не как у 2GIS. Места без адреса исключены.
- Нет данных о розетках, террасах (кроме отметки OSM), собаках (одна площадка), доступности (только отметка wheelchair=yes), мероприятиях.
- Оценки и часы собраны вручную на дату проверки; автоматическое обновление — через 2GIS API (скрипт `scripts/enrich_2gis.py`, нужен ключ).
- Время в пути на авто без учёта пробок; для автобуса и ЛРТ это оценка по остановкам OSM без расписания и номеров маршрутов (точный маршрут — в 2GIS/Google Maps); самокат считается по велопрофилю; пешеходные маршруты по данным OSM.
- Без ключа Gemini ответ шаблонный, мультиязычность (советы на языке пользователя) работает только с LLM.
- Публичные сервисы (Overpass, Nominatim, OSRM) имеют лимиты; для продакшена нужен собственный инстанс.

## 8. План развития

1. Ключ 2GIS Places API: автообновление оценок, часов и меню для всей базы.
2. Данные о мероприятиях (афиши, выставки, вечеринки) и учёт текущей даты.
3. Геолокация на устройстве с явным согласием; офлайн-режим.
4. Пользовательские оценки и отзывы с анализом тональности сервиса.
5. Расширенная доступность (пандусы, лифты), фильтр «с животными».
6. Мультиязычность в шаблонном режиме (RU/EN/KK), голосовой ввод.
7. Деплой (Cloud Run) и мониторинг качества ответов.

## 9. Соответствие критериям оценки

1. **Релевантность и полезность** — гео-фильтр + TF-IDF + критерии запроса, реальные места.
2. **Контекстуальность** — расстояние, время, категория, часы работы, группа, способ передвижения.
3. **Качество объяснений** — «почему» с подтверждёнными и неподтверждёнными критериями.
4. **UX** — три сценария на главном экране, карта с кликом по точкам, пошаговые маршруты.
5. **Креативность** — мини-маршрут из 3 мест, группы до 20 человек, критерии с ✓/?, учёт доступности по тегу OSM.
6. **Этика и приватность** — раздел 5, панель данных.
7. **Завершённость** — этот документ, тестовые сценарии, скрипты сбора данных, README.
